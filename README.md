# Тихий ход — автоматические гаражные ворота

Русскоязычный лендинг, FastAPI, SQLite и доставка заявок в Telegram. Python 3.10, без Node и внешних ресурсов. SVG-иллюстрации, скрипты и стили локальные.

## Запуск

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN='токен-бота'
export TELEGRAM_CHAT_ID='идентификатор-чата'
export SECRET_KEY="$(python3 -c 'import secrets; print(secrets.token_hex(32))')"
PORT=8090 .venv/bin/python app.py
```

Откройте http://localhost:8090. В production используйте HTTPS на обратном прокси и один процесс: лимиты хранятся в памяти. Доверенный прокси должен перезаписывать клиентский `X-Forwarded-For` либо добавлять фактический публичный адрес клиента в конец цепочки. Если цепочка заканчивается непубличным адресом, режим совместимости использует первый публичный IP; в таком режиме прокси должен удалять значения, присланные самим клиентом. Секреты не сохраняйте в git.

| Переменная | Назначение / значение по умолчанию |
|---|---|
| TELEGRAM_BOT_TOKEN | Токен от BotFather |
| TELEGRAM_CHAT_ID | ID целевого чата |
| TELEGRAM_API_BASE | `https://api.telegram.org` |
| SECRET_KEY | Постоянный случайный секрет HMAC; без него временный при запуске |
| PORT | Порт приложения `8090` (mock: `8091`) |
| LEADS_DB | Путь к SQLite, `leads.sqlite3` рядом с приложением |
| MOCK_DB | SQLite тестовых сообщений, `mock.sqlite3` |
| TRUST_PROXY | `0`; при `1` и непосредственном прокси из `TRUSTED_PROXY_IPS` используется последний корректный IP из всех заголовков `X-Forwarded-For`, если он публичный; иначе первый публичный IP. Без публичного IP или доверенного прокси используется адрес соединения. |
| TRUSTED_PROXY_IPS | Список CIDR через запятую для непосредственных доверенных прокси; по умолчанию `127.0.0.1/32,::1/128` |

## Telegram

1. Напишите **@BotFather**, отправьте `/newbot`, задайте имя и уникальный username. Сохраните токен в TELEGRAM_BOT_TOKEN.
2. Откройте своего бота и нажмите «Начать»; для группы добавьте бота и отправьте команду с упоминанием бота.
3. На доверенной машине запросите `https://api.telegram.org/bot<ТОКЕН>/getUpdates`. Найдите `message.chat.id` нужного чата (у групп обычно отрицательный), укажите в TELEGRAM_CHAT_ID. Не публикуйте URL с токеном, историю команд и ответы с личными данными.
4. Оставьте тестовую заявку и проверьте доставку.

## Проверка без Telegram

```sh
PORT=8091 .venv/bin/python mock_telegram.py
# В другом терминале:
TELEGRAM_API_BASE=http://127.0.0.1:8091 TELEGRAM_BOT_TOKEN=fake TELEGRAM_CHAT_ID=demo SECRET_KEY=local-demo-only PORT=8090 .venv/bin/python app.py
```

Mock доступен только на loopback. http://127.0.0.1:8091 показывает чат, `/messages` возвращает JSON. Для отправки получите GET `/api/form-token`, подождите минимум 3 секунды и POST JSON на `/api/lead`: `token`, `name`, `phone`, `door` (пусто / Секционные / Рулонные / Распашные), `comment`, `consent: true`, `website: ""`.

## Защита и сохранность

Honeypot незаметно принимает спам без сохранения. HMAC-токен действителен от 3 секунд до 2 часов. На IP за 10 минут можно сделать до 30 запросов к `/api/form-token` и отправить до 3 новых заявок; повторный телефон в течение 10 минут не создаёт ещё одну заявку и не расходует лимит. Российский номер с +7, 8 или без префикса нормализуется к +7. Имя 2–250 знаков, комментарий до 500. Лимит тела — 8 КиБ для JSON и 12 КиБ для URL-кодированной формы без JavaScript. CSP запрещает сторонние ресурсы и встроенные скрипты, запрещены iframe. Telegram получает экранированный HTML.

Каждая валидная уникальная заявка **сначала** записывается в SQLite со статусом `pending`, затем отправляется; результат — `sent` или `failed`. Клиенту подтверждается сохранение даже при недоступности Telegram. Автоповторов пока нет: контролируйте `SELECT * FROM leads WHERE status != 'sent'` через защищённый административный доступ и обрабатывайте заявки вручную. `pending` может остаться после аварии процесса. Резервируйте SQLite, ограничьте права на файл и каталог. Не открывайте БД через веб-сервер.

Согласуйте правовое основание передачи данных в Telegram и локализацию хранения. Организуйте удаление (в политике предел 90 дней), резервирование и мониторинг недоставленных заявок. Для нескольких воркеров нужен общий лимитер. Настройте лимит запросов и соединений на прокси; HMAC не заменяет CAPTCHA против целевых атак.
